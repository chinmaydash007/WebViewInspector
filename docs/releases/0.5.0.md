# WebView Inspector 0.5.0 — Live and Recent WebViews

**Published 22 November 2026. Both artifacts are verified on Maven Central.**

## Changes

- **Live and Recent WebViews:** switch between WebViews visible on the current
  screen and saved records from WebViews you have left. Captured URLs,
  navigation history and explicit app-load inputs survive Activity changes and
  destruction, so brief checkout/payment pages remain inspectable afterward.
- **Inspector access across Activities:** after the first visible WebView is
  detected, the floating Inspector stays available on foreground app screens,
  including native screens with no visible WebViews. Clearing Recent does not
  hide the control. Backgrounding hides it; disable/uninstall or process death
  resets the session.
- **Captures before discovery:** inputs passed through the explicit `loadUrl`
  helpers appear in Recent even if that WebView never became visible. These
  records are labelled as app-supplied inputs and do not activate the floating
  control before the first visible discovery.
- **Saved inspection:** read and copy the last recorded URL, navigation history
  and supplied headers after the original WebView is gone. Locate and live
  quick-copy remain tied to a visible, explicitly selected instance.
- **Stable instance identities:** different WebView instances keep distinct
  numbers and records, including instances that loaded the same URL.
- **Improved tabs:** a rounded Live/Recent control with one sliding selection
  surface, separate count badges, subtle press feedback, keyboard focus and
  accessible selected states. Rapid taps reverse from the current position;
  count refreshes do not restart the animation. System animation preferences,
  RTL layouts and larger fonts are supported.
- **Updated Afterframe demos:** refreshed Home, Movies, Headers and Browser
  recordings show the current Inspector UI. A fifth demo shows the floating
  control and saved inspection with no visible WebViews.

## Compatibility and data handling

The seven Java/Kotlin facade methods are unchanged. Basic still needs only one
application-wide installation; Advanced capture remains opt-in through the
existing synchronous load helpers. Both artifacts retain Android API 24 as
their minimum and WebKit 1.15.0 as the compiled/published minimum.

Recent contains observed navigation and explicitly supplied helper inputs,
rather than a complete network log. Records are bounded and held in process
memory only. Clearing, eviction, disable/uninstall or process death removes
saved data. No analytics, automatic input logging, disk persistence, upload,
JavaScript injection or WebView client replacement is added.
